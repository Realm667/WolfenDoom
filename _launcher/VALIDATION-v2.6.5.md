# Launcher v2.6.5 Validation

Date: 2026-09-06. Platform: Windows 11, .NET Framework WPF.
Game source: Realm667/WolfenDoom master, commit
e31540df4727008828b62f3faae65d637bae6af8, freshly packaged for these tests.

## Official Engine Evidence

- UZDoom 5.0.1 Windows release archive SHA-256:
  `abc39ceea3d266d471e1b5db860c8e29edba4e7ebefc3ba60a9abec13138ef74`.
- CLI help probing and binary network-identifier detection tested separately.
- 2-player and 4-player localhost lobby synchronization passed.
- Controlled autoexec `pullin` fixture did not load in multiplayer.
- A wrong-password client was not admitted during the test window; the same
  lobby subsequently admitted a client using a valid 255-byte Unicode password.
  The Windows engine did not expose its rejection dialog text on stdout, so the
  specific dialog message was not validated by this automated test.
- Two local engine processes entered C1M1, saved a co-op game, and exited cleanly.
- Both processes restored that real save using production command construction
  and native-folder preparation. Logs confirmed restoration of TestPlayer0 and
  TestPlayer1 data on both peers. The original save remained unchanged.
- Official UZDoom 4.14.3 passed a 2-player localhost handshake using commands
  generated by the launcher and the same fresh BoA archive.

UZDoom 5.0.1 uses `NetGame/<IWAD AutoName>` beneath its native portable or Windows
Saved Games root for network saves, regardless of `-savedir` or `save_dir`.
Co-op restoration therefore stages verified local copies and sends a filename,
not an absolute path. The session file carries a save hash, not the save payload.

## Automated Regression Coverage

- `Test-Core.ps1`: legacy/current command generation, launch options and locales.
- `Test-V25.ps1`: profiles, save identity/filtering and session compatibility.
- `Test-V26.ps1`: preflight, release integrity and add-on ordering/conflicts.
- `Test-V265.ps1`: UTF-8 password boundaries, invalid Unicode, capability cache,
  host-only overrides, value ranges, session v1/v2, password privacy, co-op map
  metadata, player count, engine/game bindings, imported save checksums, user and
  portable NetGame roots, and repeatable staging without overwriting source saves.
- `Test-Optimizations.ps1`: cache/invalidation and atomic-write regressions, real
  WPF controls, collapsed/expanded profiles, separate campaign sections, retained
  Play behavior, direct Continue action, save removal and narrow/wide layout.
- Controller Accept was injected into the WPF handler and correctly expanded
  and collapsed the profile accordion. This is not physical-device testing.
- WPF render captures inspected with bundled logo/font and completed animations.
- ZIP contents and deployed release files are checked against SHA-256 manifest
  entries. Canonical LF release text and scoped Git attributes preserve these
  hashes across checkouts without changing the user's launcher INI.

## Coverage Limits

- Localhost smoke tests are not a full multiplayer certification.
- Separate physical machines, LAN routers, NAT traversal and WAN were not tested.
- Full campaign inventory, keys, pickups, checkpoints, respawns and custom ACS
  cinematics were not exercised end-to-end with the engine's `-coop` preset.
- No physical XInput controller was used for this build's validation.
- New interface strings have English defaults and German translations; existing
  fallback behavior applies to interface languages without a new translation.
- No signing certificate was supplied; binaries remain unsigned.
